# AssegaiPHP RabbitMQ 1.1.2

RabbitMQ 1.1.2 decouples application bootstrap from broker availability.

## What changed

- makes queue construction and `create()` configuration-only
- defers the AMQP connection, channel creation, queue declaration, exchange declaration, and binding until the first broker-backed operation
- leaves failed first-use connections uncached so later operations can retry after RabbitMQ recovers
- detects closed cached transports and reconnects before the next operation
- wraps every enqueue failure from `Throwable` in the queue exception contract
- closes partially established transports after failed topology setup
- uses `localhost` when no host is configured, matching PhpAmqpLib's default

## Compatibility

- requires `assegaiphp/common:^0.10.1`
- supports named application resolution through `assegaiphp/core:^0.10.1`
- remains compatible with `assegaiphp/console:^0.10.3`

## Upgrade notes

No application code changes are required. Existing `#[InjectQueue]` services can now be resolved while RabbitMQ is unavailable. A connection failure surfaces from the first `add()` or `process()` operation that needs the broker, where the application or worker can report it appropriately.

Upgrade the coordinated stack together:

```bash
composer require assegaiphp/rabbitmq:^1.1.2 assegaiphp/core:^0.10.1 assegaiphp/common:^0.10.1 --with-all-dependencies
```
